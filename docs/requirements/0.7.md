# Requirements · Version 0.7 (proposal)

**Status:** proposal for review, 2026-10-13. Nothing here is built. Once the
owner has answered the open questions (§7), the accepted requirements become
changes to [SPEC.md](../../SPEC.md) on this branch, committed before any code
(AGENTS.md rule 1), each choice with its decision record.

**Builds on:** version 0.6 (pull request #2). **Sources:** the owner's third
playtest ([notes](../playtests/2026-10-13-owner.md)) and its round log (828
rounds of 0.6), plus ideas from earlier playtests that were held back.

## 1. Why a bigger iteration

Version 0.6 "plays pretty smooth now": the in-place marks read naturally, World
1 is fair, the clock rarely bites. What the playtest asks for next is a game
with more shape:

1. **Speed should earn something.** The clock is only pass or fail. In the log,
   26 of 720 timed rounds ran out; everything else counted the same whether it
   took 1 s or 9 s.
2. **Runs are short and flat.** Challenges have 8 rounds, bosses 10, all with
   the same difficulty from first to last. The owner asks for 10–20 rounds per
   challenge, and bosses of 3 waves of 10 rounds with rising difficulty.
3. **Failing is invisible until the end.** A lives indicator should show how
   many rounds can still fail.
4. **Some rounds don't need the new move.** In 2.1, `2k` ties with `kk` and `2x`
   with `xx`, so counts feel pointless. In 2.2, targets one to three cells away
   are reached as fast with `l`.
5. **Inserted spaces are invisible.** Green ghost text can't show a space, and
   marks under the cursor can't be seen.
6. **The game's parts need agreed names.** Players, notes and code say level,
   item, room, stage, round and turn for overlapping things.

## 2. Goals and non-goals

Goals for 0.7:

- Reward speed with time stars, without making the time limit harsher.
- Longer challenges and bosses with a difficulty curve, lives and waves.
- Every round in a stage's challenge needs that stage's move, and pays for it.
- Marks that are always visible, including spaces and under the cursor.
- One glossary of terms used by the UI, the docs and the code.

Non-goals (unchanged from 0.6 unless noted):

- New moves. `d^` and `c^` are not new: `^` (2.4) and `d`/`c` (World 3) are
  already taught; this version only adds rounds for them.
- Insert-mode editing beyond typing text (see open question Q5).
- Difficulty settings, sound, long-term statistics.

## 3. Terms (proposal for `docs/glossary.md`)

One name per thing, used in the UI, the docs, the spec and the code. The
playtest's "level", "item" and "room" map onto these:

| Term | Meaning | Not called |
| --- | --- | --- |
| World | A group of stages ending in a boss (World 1 · First steps) | chapter |
| Stage | One move or move family taught in a world (2.2 `w b`) | level |
| Stage page | The stage's screen in the menu: explainer, drill, challenge | explainer screen |
| Drill | Untimed practice of a stage: basics, then combined rounds | tutorial |
| Challenge | A stage's timed test; earns the stage's stars | level |
| Boss | A world's final timed test, in waves | boss level |
| Wave | A block of a boss's rounds with its own difficulty curve | phase |
| Run | One play of a drill, challenge or boss, start to summary | attempt |
| Round | One task in a run: reach a target or make an edit | item, room |
| Chain | A round of 2 or more steps, done in order | multi-turn item |
| Step | One part of a chain | turn |
| Par | The fewest keys that solve a round with learned moves | optimum |
| Key stars | 0–3 stars for keys used compared with par | stars |
| Time stars | 0–3 stars for the time a round took (new, §4 A1) | speed stars |
| Lives | How many more rounds a run can fail and still pass (new) | hearts |
| Marks | What the buffer shows: target (cell), strike (delete), ghost (insert) | diff, markup |
| Summary | The screen after a run, one row per round | results |
| Review | One round from a summary, as it started | post-mortem |
| Replay | Playing a reviewed round again, untimed and unsaved | practice |

Acceptance: `docs/glossary.md` exists with this table; AGENTS.md tells
contributors to use it and to add a term there before using a new one; UI
strings and the spec use only these terms (a test greps UI strings for the
"not called" words).

## 4. Requirements

Each requirement has an id, where it comes from, what it means, and how to
tell it is done. "PT3" is the third playtest, "log" its round log.

### A. Scoring and pacing

**A1. Time stars per round.** (PT3: "intervals for the used time that give
different amounts of points … three for below the toughest threshold, two and
one for a bit longer, and none for a timeout")

- Every timed round earns time stars next to its key stars:
  ★★★ fast, ★★ steady, ★ before the limit, 0 on a timeout.
- Starting thresholds, from the owner's own times in the log (to be retuned
  once other players have played):

  | Time stars | Solved within | Owner's solved rounds in the log |
  | --- | --- | --- |
  | ★★★ | 0.5 s + 0.4 s per par key | 39 % |
  | ★★ | 1.5 s + 0.55 s per par key | 36 % |
  | ★ | the time limit (5 s + 0.8 s per key + 1 s per extra chain step) | 24 % |

  Chains add 1 s per step after the first to every tier, as the limit does.
- Drills show time stars but nothing depends on them (open question Q4).
- Done when: the result line, the summary and the review show both kinds of
  stars; the thresholds live in `config.lua`; the round log records the time
  tier.

**A2. The clock shows the tier as it drops.** (PT3: "a visual indicator in the
UI that changes every time you drop a tier")

- The header shows the three time stars beside the countdown; one goes dark at
  each threshold, and the countdown changes color with it (normal, then
  amber, then the warning color for the last 2 s).
- Done when: a test drives the clock past each threshold and reads the header.

**A3. Stage stars from keys and time.** How the two kinds of round stars make a
stage's rating is open question Q1. Whatever is chosen, passing stays about
rounds solved (A4), so being slow never fails a run before the limit does.

**A4. Lives.** (PT3: "a lives indicator at the top of the screen of how many
rounds you can lose before you fail to advance")

- Challenges and bosses start with lives = rounds that may fail and still pass
  (25 % of the rounds, rounded down: 5 of 20, 7 of 30).
- A timeout costs a life. The header shows lives as hearts (`♥♥♥♡♡`); losing
  one flashes the header once.
- At 0 lives with rounds left, the run ends at once with its summary ("Out of
  lives"), because it can no longer pass (open question Q2).
- Done when: the header shows lives; a run with all lives lost ends early; the
  pass rule and the lives count agree for every configured length.

**A5. `<CR>` on a summary continues.** (PT3: "enter on a finished challenge
leads to the details … instead of the next level. Inspecting details should get
a different button.")

- On every summary, `<CR>` and `n` do the same: start the challenge after a
  drill, the next stage or world after a pass, retry after a fail.
- `v` opens the review of the round under the cursor (`j`/`k` still choose the
  round). The status line reads
  `<CR> next stage   v view round   r retry   m menu`.
- Supersedes the summary part of decision 0017.

### B. Longer runs with a curve

**B1. Challenges of 20 rounds.** (PT3: "a minimum of 10 rounds, maybe rather
20")

- 20 rounds (configurable, at least 10): 6 basics then 14 combined, every one
  needing the stage's move as now.
- Rounds rise in difficulty along one S-curve (B3) instead of a random order.
- Drills stay at 6 rounds.
- Done when: the 200-seed stage test checks 20-round plans; a challenge takes
  about 2 minutes at the owner's pace.

**B2. Bosses of 3 waves × 10 rounds.** (PT3: "bossfights maybe more like 30
rounds, separated into 3 waves of 10 rounds each … an S curve per wave … that
gets steeper for each of the three waves")

- Each wave follows its own S-curve of difficulty (B3); each wave starts higher,
  rises more steeply and ends higher than the last.
- Between waves, a break screen shows the wave's result, lives left and a 3-2-1
  countdown into the next wave. Lives carry over between waves.
- The header shows `Wave 2/3 · round 4/10`.
- The concept report and the summary cover the whole boss, with a line per
  wave.
- Done when: a boss plan has 30 rounds in 3 waves whose difficulty follows the
  curves in B3; the end-to-end test plays all three waves.

**B3. Difficulty model.** What "harder" means, so curves can be generated and
tested:

- A round's difficulty `d` (0 to 1) sets its shape:

  | d | Chain steps | Move families at least | Par |
  | --- | --- | --- | --- |
  | below 0.35 | 1 | 2 (mixed) | 3–7 keys |
  | 0.35–0.7 | 2 | 2 | 6–12 keys |
  | 0.7–0.9 | 3 | 3 | 9–16 keys |
  | 0.9 and up | 3–4 | 3 | 12–20 keys |

- The curve for round `i` of `n` in a wave is
  `d(i) = low + (high − low) · S(i)`, with `S` a logistic curve scaled to run
  from 0 to 1 and steepness `k`. Starting values:

  | Wave | low | high | k |
  | --- | --- | --- | --- |
  | 1 | 0.1 | 0.5 | 0.8 |
  | 2 | 0.3 | 0.75 | 1.1 |
  | 3 | 0.5 | 1.0 | 1.5 |
  | Challenge (one curve) | 0.0 | 0.6 | 0.6 |

- The generator retries until a round's par and steps fall in the band for its
  `d`; all natural-distance rules still apply.
- Done when: a test generates 50 bosses per world and checks every round's
  band; generation stays within the 500 ms budget per round (per step for
  chains).

### C. Rounds that need the move

**C1. The new move must pay.** (PT3 on 2.1: "I don't get to use my new move
because there are so many instances of items being waaay too close to warrant
using numbers")

- In a stage's drill and challenge, every round's par must be at least one key
  shorter than the best solution without the stage's move. The solver checks
  this by solving again with the stage's move family banned.
- For counts (2.1) this means at least 3 lines (`3j` beats `jjj`, `2j` only
  ties `jj`) and at least 3 stray letters for `x` counts.
- Later stages and bosses may still use the move where it only ties.
- Done when: the 200-seed stage test checks the margin for every stage.

**C2. Word targets beyond a few cells.** (PT3 on 2.2: "for one to three
characters it's a bit lame")

- In 2.2 (`w b`) and 2.3 (`e`), targets are 1 to 4 words away and at least 4
  cells away.
- Done when: the stage test checks the distance for every round of those
  stages.

**C3. Prefix and suffix edits.** (PT3: "templates … for rounds that have you
enter a prefix or a postfix to the start or the end of a word, maybe a comma or
a few letters")

- New combined round kinds in 2.2 and 2.3, reused by later bosses: move to a
  word's start or end, then `i` or `a` (`2wire<Esc>`, `3ea,<Esc>`, `eas<Esc>`).
- Additions come from a list of common affixes: `s`, `ed`, `ing`, `er`, `re`,
  `un`, `,`, `.`, `:`, `;`.
- Done when: each of the two stages shows such rounds in at least a quarter of
  its combined rounds over 200 seeds.

**C4. Line edges delete, not insert.** (PT3 on 2.4: "it doesn't make as much
sense … to directly do an edit, because you would rather use `A` or `I`")

- 2.4 combined rounds pair `0 ^ $` with `x` at the line's edges (`$x`, `^2x`)
  instead of insertions, which `A` and `I` do better.
- World 3 picks this up with `d$`, `d0` and `d^` (C5).

**C5. Backwards to the line start: `d^` and `c^`.** (PT3: "3.2 and 3.3 could
use something like d^ or c^ backwards from the cursor. Especially relevant in
programming.")

- 3.1 (delete) gains `d^` rounds and 3.2 (change) `c^` rounds on indented code
  lines, next to `d0`, `d3b` and deletes from the middle of a word (which the
  playtest liked).
- Done when: those rounds appear in the stage tests; the solver finds `d^`
  where it is par.

**C6. Word motions across line ends before the boss.** (PT3: in the World 3
boss, "`b` wrapping over into the last line" was new)

- 2.2 combined rounds include `w`/`b` across a line end (from a line's first
  word back to the previous line's last word, and the other way).
- Done when: at least one round in ten of 2.2's combined rounds wraps.

**C7. From World 3 on, no plain moves in challenges and bosses.** (PT3: "after
this world you shouldn't get any raw movements than the ones you just learned
anymore, otherwise only movements that are combined with stuff")

- From World 3 on, every round in a challenge or boss includes an edit, except
  rounds that practise that world's own new motions (`f F t T` in World 4).
  Chains no longer have plain "go here" steps there.

**C8. Few stray letters, solvable the practical way.** (PT3, World 2 boss:
"multiple characters to remove at the end of a word" felt weird)

- Stray letters at a word's end are 1 or 2, so `e` then `x` or `xx` from the
  end is par. More junk than that becomes a word to replace with `cw`, and only
  once `c` is learned.

### D. Marks you can always see

**D1. Visible insertions.** (PT3 on 1.3/1.4: "impossible to see under the
cursor or on a blank space")

- Ghost text is underlined, like deletions are struck through.
- A space in ghost text is drawn as `␣` (one cell, so columns don't move).
- Done when: the marks test checks the underline and the `␣`.

**D2. Marks under the cursor.** A block cursor hides the mark of the cell it is
on.

- Deletions get a background tint as well as the strike, so the cell under
  the cursor still shows red.
- The header's prompt line names what is left to do in words, updated with the
  marks: `Delete: q  ·  Type: tent␣`. Nobody has to spend keys to look.
- Done when: a test edits halfway and reads the header.

### E. Conventions and data

**E1. Glossary.** §3 becomes `docs/glossary.md` (see its acceptance there).

**E2. Visual conventions.** The glossary also fixes one look per element:
target (block, yellow), strike (red, struck through, tinted), ghost (green,
underlined, `␣` for spaces), time tier colors, hearts. Screens, the explainer
examples and the README use them.

**E3. Round log.** Each logged round adds `time_tier`, `wave`, `lives_left` and
the target difficulty `d`, so the next tuning can be checked against data the
way 0.6 was.

## 5. Order of work

Small, visible pieces first, so each can be played before the next starts:

1. **Marks and keys (D1, D2, A5, E1, E2).** Smallest changes with the most
   immediate effect.
2. **Time stars and lives (A1–A4, E3).**
3. **Rounds that need the move (C1–C8).** Generator and solver work, covered by
   the 200-seed tests.
4. **Longer runs and waves (B1–B3).** Builds on lives and time stars.
5. **Playtest and tune** the thresholds, curves and lengths from the log.

## 6. What changes in the spec

§4 Core loop (lengths, waves, lives), §5 Rounds (marks, time tiers, lives), §6
Scoring (time stars, stage stars), §7 Curriculum tables (2.1–2.4, 3.1, 3.2,

## 8. Out of scope for 0.7

New moves (text objects, search, yank and put, visual mode), difficulty
settings, a review of rounds from earlier sessions (the log keeps the seeds, so
it could come later), sound, and porting to plain Vim.
